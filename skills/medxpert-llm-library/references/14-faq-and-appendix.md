## MedXpert-八、常见问题

**Q: 模型回答很慢怎么办？**
A: 换更小的模型（7B → 3B）；关闭其他占内存的程序；如果有独显，确认 Ollama 用了 GPU（`ollama ps` 看 GPU 列）。

**Q: 中文回答质量不好？**
A: 确保用 Qwen2.5 系列（中文最好）；换更大的模型（3B → 7B）；在 prompt 里加"请用中文回答"。

**Q: 知识库文件太多，模型记不住怎么办？**
A: 升级到进阶档（用 RAG 工具做向量检索）；或把大文件拆分成小文件，按主题分目录。

**Q: Ollama 在中国网络下拉不动模型？**
A: 用 gh-proxy.com 代理下载安装包；拉模型时用 timeout 包装自动重试（见方案 A）；先拉小模型。

**Q: 可以多台电脑共享知识库吗？**
A: 把 `my-library/` 目录放网盘（微云/坚果云）或用 Git 同步；Ollama 各装各的，知识库文件共享。

**Q: 需要联网吗？**
A: 装好模型后完全离线可用。只有下载模型和安装时需要联网。

**Q: DSH 是什么？必须要装吗？**
A: DSH（DeepSeek Harness）是本地大模型的前端 UI，给 Ollama 套一个 ChatGPT 风格的界面。不是必须的——命令行 `ollama run` 也能用，但 DSH 体验好得多，还支持 Agent 模式。目前很火，推荐装。

**Q: DSH 装上后一直 EMPTY_RESPONSE 怎么办？**
A: 99% 是 pi-ai 补丁没打。DSH 依赖的 `@earendil-works/pi-ai/dist/models.js` 里 `calculateCost` 访问 `model.cost.tiers`，本地免费模型没有 cost 字段会报错。在 `calculateCost` 开头加 `if (!model.cost) model.cost = { input:0, output:0, cacheRead:0, cacheWrite:0, tiers:[] };` 即可。详见"二补"板块的踩坑清单。

**Q: 装了好几个模型，同时跑会不会内存不够？**
A: 不会。Ollama 是"用谁加载谁"——调哪个模型才加载哪个，调完自动释放。只要**单个最大模型**不超过内存就没事。想手动控制可以设 `OLLAMA_KEEP_ALIVE`（保持驻留时间）。

**Q: 建图书馆是不是一个模型就够了？**
A: 能跑，但多模型协作效果明显更好。小模型干筛选（快），Qwen 干中文摘要（准），DeepSeek 干交叉验证（深），Embedding 干向量化（专）。详见"三补"板块，有完整的流水线分工表和代码示例。

**Q: RAG 问答总是答非所问/答不上来？**
A: 检查三件事：① Embedding 是不是 bge-m3（英文模型转中文全乱）；② 切块大小是否 500~800（太大答泛、太小答碎）；③ 是否用了混合检索（专业术语加 BM25）。详见"四补"。

**Q: RAG 回答会编造怎么办？**
A: ① prompt 加"只依据资料+标注来源+没有就说没有"；② 降低 Top-K（5~8 块太多就减）；③ 提高检索阈值过滤低相关片段。

**Q: 知识库怎么变现？第一步做什么？**
A: 别先想收费。第一步：把图书馆精华做成免费内容开馆引流（五补二/五补三）；第二步：开公众号/知识星球沉淀关注者；第三步：有人气了再上会员借书证（¥99/年）。详见"五补"和"商业逻辑"。

**Q: 没粉丝没流量，做这个还有意义吗？**
A: 有。图书馆首先是**给你自己用的工具**（提效/积累），变现是"用起来之后"的副产品。先用它管好你的知识，内容会自己长出读者。

**Q: 公司电脑上搭知识库要注意什么？**
A: ① 外部资料入库前必须脱敏（5.2）；② 本机不装远程控制软件、不共享（5.9）；③ 权限分级（管理员/编辑/只读）；④ 发布任何东西前过发布门禁四层检查（`publish-quality-gate`）。

**Q: 文件被误删/改坏了能找回吗？**
A: 只要用了 Git 就能找回：`git checkout <commit-hash> -- <文件名>` 恢复任意历史版本；或 `git log --oneline` 看历史。这就是"文件有跟踪"的意义（5.7）。

**Q: 一个文件的内容放多久该更新？**
A: 建议"月度体检"（5.5）：每月让模型对比最新法规/标准，过时的标 `status: 已过时`，确认后更新或归档（99-归档/）。法规类内容尤其注意"以现行版为准"。

## 附录：性能调优（Ollama 参数怎么调）

| 参数 | 怎么设 | 效果 |
|------|--------|------|
| `OLLAMA_KEEP_ALIVE` | 设为 `5m` 或 `-1`（常驻） | 模型驻留内存，连续问答不重载（省时间费内存） |
| `OLLAMA_NUM_PARALLEL` | 设为 1~2 | 并行请求数，低配设 1 防内存爆 |
| `OLLAMA_MAX_LOADED_MODELS` | 设为 1 | 同时加载模型数，低配设 1 |
| `num_ctx`（上下文） | 8192~16384 足够 | 越大越吃内存，别盲目开满 32768 |
| `temperature` | 0.2~0.4（知识问答）/ 0.7（创作） | 知识库问答用低温度减少编造 |
| `num_gpu`（显卡层数） | 有独显设 999（全卸载 GPU）；纯 CPU 设 0 | 让模型跑在 GPU 上提速 |
| `top_p` | 0.9 默认 | 采样控制，一般不用动 |

> **低配优化三板斧再强调**：Q4 量化（体积砍 1/3）、控制上下文（8192~16384）、串行处理（批量任务一个一个跑）。

## 附录：术语表（小白速查）

| 术语 | 大白话解释 |
|------|-----------|
| **大模型 / LLM** | 像 ChatGPT 那样的 AI 大脑，能理解文字、生成回答 |
| **本地模型** | 跑在你自己电脑上的大模型，不依赖云端 |
| **Ollama** | 一个让你在电脑上一键装/跑本地模型的工具 |
| **Q4 量化** | 把模型体积压缩到 1/3~1/4 的技术，质量损失很小，低配必备 |
| **3B / 7B / 14B** | 模型参数规模，越大越聪明也越吃内存（B = 十亿参数） |
| **Embedding 模型** | 把文字变成"向量"（一串数字）的模型，用于搜索和 RAG |
| **向量 / 向量化** | 把文字转成数字坐标，语义相近的文字坐标也相近 |
| **RAG** | 检索增强生成：先在你的知识库里搜索相关内容，再让模型基于它回答 |
| **Top-K** | RAG 检索时取最相关的 K 个片段（通常 5~8） |
| **切块 / Chunk** | 把长文档切成小块再处理（每块 500~800 字） |
| **GGUF** | 一种模型文件格式（llama.cpp/Ollama 用的量化格式） |
| **DSH / DeepSeek Harness** | 给本地模型套的 ChatGPT 风格界面 |
| **前端 UI** | 用户看到的界面层（DSH、AnythingLLM 都属于） |
| **后端引擎** | 真正跑模型的部分（Ollama 属于） |
| **RAG 工具** | AnythingLLM/Cherry Studio 这类"上传文档就能问答"的工具 |
| **MECE** | 分类原则：相互独立、完全穷尽（一个文件只归一类） |
| **LLMs.txt** | 给 AI 看的网站/知识库地图文件，告诉 AI 你的库有什么 |
| **L0~L3** | 内容分级：免费公开/关注者/会员/定制 |
| **B 端** | 面向企业客户（相对 C 端个人消费者） |

## 附录：模板文件清单（templates/ 目录，直接复制用）

本 Skill 附带 `templates/` 目录，内含可直接复制使用的模板：

| 文件 | 用途 |
|------|------|
| `templates/llms.txt` | AI 图书馆地图（放图书馆根目录，AI 一进来先读） |
