## MedXpert-四补、把图书馆做成 RAG（检索增强问答）

> **RAG（Retrieval-Augmented Generation）= 先检索、再回答。** 大模型不认识你的知识库，RAG 就是：把问题去知识库里找最相关的片段，拼给模型，让它**基于这些片段回答**。解决"模型记不住你的库"和"模型瞎编"两大痛点。

### RAG 工作流（30 秒看懂）

```
离线建库：文档 → 切块 → 向量化 → 存入向量数据库
                                ↓
在线问答：问题 → 向量化 → 检索 Top-K 相关片段 → 拼 Prompt → 模型基于片段回答（带来源）
```

| 环节 | 做什么 | 用什么 |
|------|--------|--------|
| 切块 | 长文档切成 500~800 字符的小块 | LangChain `RecursiveCharacterTextSplitter` |
| 向量化 | 每块转成向量（数字） | **bge-m3**（中文最好）/ nomic-embed-text（快）/ mxbai-embed-large（质量高） |
| 存储 | 向量入库 | Chroma（轻量）/ Qdrant（功能全）/ Milvus（大规模） |
| 检索 | 找最相似的 Top-K 块 | 向量相似度 + 可选关键词 BM25（混合检索） |
| 生成 | 模型基于片段回答 | **Qwen2.5:7B**（中文主力，见三补） |

### 两种落地方式

**方式 A：工具型（零代码，30 分钟上线）** — 大多数人选这个
- **AnythingLLM**：开箱即用，上传文档即 RAG，内置向量库，支持 Ollama
- **Cherry Studio**：国产，界面友好，知识库 + 对话一体
- **RAGFlow**：文档解析最强（PDF/表格/扫描件），适合复杂文档
- 步骤：装工具 → 连 Ollama → 选 embedding 模型 → 上传文档 → 开问

**方式 B：代码型（可定制，1-3 天）** — 要深度定制/产品化时选
- 完整示例见"四、高级档"（LangChain + Chroma + Ollama 代码）
- 适合：Web 界面、API 服务、多知识库隔离、自定义 prompt

### 本地 RAG 最佳实践（实战经验）

| 项 | 推荐配置 | 原因 |
|----|---------|------|
| **Embedding 模型** | **bge-m3**（中文） | 中文语义检索效果最好，1GB 体积 |
| **切块大小** | 500~800 字符，overlap 50 | 太大超上下文/太碎丢语义 |
| **检索 Top-K** | 5~8 块 | 太少漏信息、太多灌噪声 |
| **混合检索** | 向量 + 关键词 BM25 | 专业术语/编号用关键词更准 |
| **Prompt 模板** | 要求"标注来源文件，没有就直说" | 防止编造、可溯源 |
| **知识量上限** | 单库 <1000 文件，多了分库 | 检索精度随规模下降 |

**推荐 Prompt 模板**（问答质量关键）：
```
你是知识库助手。请基于以下资料回答用户问题：
1. 只依据资料内容回答，不要编造
2. 回答末尾标注信息来源文件名
3. 资料中没有的信息，直接说"知识库中未找到"

资料：
{检索到的片段}

问题：{用户问题}
```

### RAG 效果自测（5 分钟验收）

准备 10 个问题（5 个库内能答的 + 5 个库外问的），逐条测：
| 检查项 | 通过标准 |
|--------|---------|
| 召回 | 库内问题能答上来（找到片段） |
| 忠实 | 回答内容能在片段里找到依据（不编造） |
| 拒答 | 库外问题明确说"未找到"，不硬编 |
| 溯源 | 回答标注了来源文件 |

> 四个全过 = RAG 合格。编造多 → 调 prompt/降 Top-K；答不上 → 换 bge-m3/调切块。

### RAG 踩坑清单

| 坑 | 现象 | 解法 |
|----|------|------|
| **英文 embedding 转中文** | 中文语义检索全乱 | 换 bge-m3 |
| 切块太大 | 检索命中整篇文档，回答泛泛 | 调到 500~800 |
| 切块太小 | 片段零碎，答不到点 | 加大到 800 并加 overlap |
| 向量检索不到专业术语 | 法规编号"GMP-2025"搜不到 | 加 BM25 关键词检索 |
| 模型瞎编 | 回答内容片段里没有 | prompt 加"只依据资料+标注来源" |
| 文档解析乱 | PDF 表格/扫描件文字错乱 | 用 RAGFlow 或先 OCR（VL 模型） |

### 与 DSH/多模型配合（进阶玩法）

- **RAG 问答用 AnythingLLM**（检索强）+ **日常对话用 DSH**（界面好）——各干各的
- **夜间重建索引**：新文档入库后，夜间批量重建向量库（结合 5.6 夜间任务）
- **多知识库隔离**：法规库/产品库/笔记库分开建，问答时指定库
- **问答质量不够时**：检索用 bge-m3 + 7B 生成；复杂问题可切 DeepSeek-R1 深度回答
